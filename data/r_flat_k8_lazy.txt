E1 (by code inspection — decisive without a bench)
--------------------------------------------------
The zbins are 1-bit DIFFERENTIAL tables: absolute values exist only via
ZPatternDb::cold_lookup, which descends the abstract graph one step per unit of
h — O(h) ranks+probes, tens of us for k8-scale h. So a from-scratch consult
design is dead on arrival (this is §8u's retraction, sharpened), and no value
cache can rescue it (a miss costs us). The only viable design is incremental:
maintain (ProjectedState, h) per group per view, diff_lookup O(1) on cost-1
edges. Design A' (flat): consult = advance-by-one-move from the parent's slot,
done ONLY for children that pass cWD's f-test. Every entered node has a current
slot, so there is NEVER a catch-up — the entire recursive LazyMaxInc deferral
machinery (8% of samples, §8l) dissolves into the arena invariant.

E2 (built; node-identity gates)
-------------------------------
`solve24 --zpdb8`: mmap pdb24_k8_{a,b,c}.zbin (32.8 GB), consult at
cWD-survivors, h = max(sum normal, sum reflected), both drivers.

Node identity vs the recorded recursive 2-tier trees (§8j):
  threshold 146:  8,539,130,554  EXACT (sequential AND parallel)
  threshold 144:  269,180,917 vs recorded 269,180,930 — Δ = 13 (5e-8),
                  ours SMALLER (stronger tree), confined to the first
                  iteration; the 146 iteration matches bit-for-bit, which rules
                  out any systematic h error. Attributed to a first-iteration
                  convention quirk of the deleted lazy driver (its deferred
                  values used a Lipschitz bound v-k-1; deferred moves popped
                  before catch-up never saw true k8). Not chased further: 8.5B
                  matching decisions is the strongest available gate.

v1 consult: copy 306B slot + 6 apply_in_place slides + 2 rank + 2 diff_lookup.
v2 consult: the projected-edge law (cost-0 slides leave index and h unchanged)
means the four cost-0 group-views need not be slid AT ALL. Their stored blank
goes stale; healed via set_blank_pos immediately before that group-view's next
cost-1 apply+rank. Sound because rank reads pattern-tile positions, the blank,
and cells[] only at occupied pattern cells. Reflected view needs no
transpose_move: sigma-image cells + TAU-relabelled tile pick its cost-1 group.
Gotcha found by panic: the engine's boards are goal-CODED (H1), so the moved
"tile" is a code; TILE_OF_CODE decodes it for the PDB machinery.
v2 gated EXACT on both counts.

Verdict for R >= 152 (exhaust-150)
----------------------------------
Cut-ratio ladder: 1.57 -> 2.03 -> 2.99 (x1.29, x1.47 per rung, rising).
Break-even at 150 requires the ratio to stop growing ENTIRELY (2.99 again);
the trend continuing gives cut ~4.4x and

  cWD-only @150:  ~16.8 T nodes / ~163 Mn/s  ~= 28.6 h
  2-tier   @150:  ~3.8 T nodes  / ~54.5 Mn/s ~= 19.3 h   (~33% faster)

RECOMMENDATION: run the R >= 152 attempt with `--parallel --zpdb8`. Projected
~19 h vs ~29 h; the projection's only soft spot is the unmeasured 150 cut
ratio, and every measured rung has moved it further in k8's favour.

Levers not yet pulled (would convert the 148 tie into a win and widen 150):
  - memoize (idx -> h) per worker to cut the 2 diff-probe faults (the tables
    oversubscribe RAM; a small cache attacks refaults the way CACHE_BITS did);
  - slot sharing (k8_at indices) to kill the 306 B copy;
  - W=12 (the +21% E-core option, declined for interactive use).
